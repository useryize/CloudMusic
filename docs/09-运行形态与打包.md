# 云音乐 PC 端运行形态与打包

> 范围：本地 Node 服务的形态设计、本地鉴权、凭证管理、安装包构建。
> 定位：`08` 是架构总纲，本文是**运行形态的落地细化**，并对 `08` 的 5 处做了修订（见 §0）。
> 不写什么：页面拆解（`08` §9）、视觉细节（`07`）、接口字段（`02`~`04`）。

---

## 0. 本文与 `08` 的关系

`08` 最初按「Electron 主进程 + IPC」设计，私钥不出主进程。现在的目标变了：**产物既要能用 `node` 直接跑，也要能打成安装包**。这两种跑法要求业务逻辑不依赖 Electron API，因此进程间通道从 `contextBridge` 换成本地 HTTP。

受影响的是 `08` 的以下 6 处，本文对应小节**取代**之，涉及 5 个章节（3 / 4 / 5 / 7 / 13），`08` 其余 13 节不变：

| `08` 小节 | 本文对应 | 变化 |
|---|---|---|
| §3 技术栈（运行时行） | §3 | 运行时从「Electron」改为「Node 20+（Electron 仅作外壳）」 |
| §4 进程模型与安全边界 | §5、§6 | IPC 通道表 → HTTP 路由表 + 本地鉴权 |
| §5 目录结构 | §3 | `src/main` + `src/renderer` → `packages/*` + `apps/*` |
| §7.1 签名位置 | §3、§5.2 | 「主进程」→「`packages/core`」，签名代码一字未改 |
| §7.2 请求封装 | §5.2 | `window.api.request` → `fetch('/api/rpc')` |
| §13 工程化 scripts | §9 | 增加打包、SEA、密钥扫描 |

**未受影响**：路由与页面（§6）、数据层 TTL（§7.3–7.5）、状态管理（§8）、设计 token（§10）、性能预算（§11）、里程碑（§14）、风险（§15）。

## 1. 结论

**一个本地 Node 进程承担全部服务端职责，前端是纯静态资源，Electron 只当外壳。**

```
            ┌──────────────────────────────────────┐
            │  server（Node，127.0.0.1:随机端口）   │
            │  ├─ /api/rpc       签名 + 转发        │
            │  ├─ /api/auth/*    二维码 / 续期      │
            │  ├─ /api/audio     音频代理（Range）  │
            │  └─ /*             静态资源 + SPA     │
            └───────────────┬──────────────────────┘
                            │ 同一个端口
        ┌───────────────────┼───────────────────┐
        │                   │                   │
   node 直跑           Electron 壳         SEA 单文件
   浏览器访问          窗口 loadURL        双击启动
```

三条设计约束：

1. **`packages/core` 不 import 任何 Electron 模块**，只用 `node:crypto` / `node:fs` / `fetch`。这是「一套代码三种出口」的前提。
2. **`apps/server` 是唯一入口**，对外只暴露一个 `startServer()` 函数。三种形态都调它。
3. **端口用 `0` 让系统分配**，不硬编码、不做 +1 重试。实际端口写入 `runtime.json` 供外壳读取。

## 2. 为什么不用 IPC

`08` 选 IPC 的理由是「私钥不出主进程」。换成 HTTP 后，这条理由仍然成立——私钥依然只在 server 进程内存里，浏览器拿不到。代价是安全边界从「进程隔离」变成「本机端口 + 鉴权」，多了一份责任（§6）。

| 维度 | IPC（`08` 原方案） | 本地 HTTP（本文） |
|---|---|---|
| 能用 `node` 直接跑 | ❌ 必须有 Electron | ✅ |
| 能打包安装包 | ✅ | ✅ |
| 私钥位置 | 主进程 | server 进程（同等安全） |
| 前端调试 | 只能在 Electron 窗口里 | 任意浏览器 + DevTools，可手机同局域网调试 |
| 热更新前端 | 需重新加载窗口 | 刷新页面即可 |
| 额外风险 | 无 | 本机任意网页可访问端口，**必须做 §6 的鉴权** |
| 音频 Range 请求 | 主进程代取，天然可控 | 需自己实现 Range 透传（§5.4） |

**结论**：多花的成本集中在 §6（约 60 行鉴权代码）和 §5.4（约 40 行 Range 处理）。换来的是产物形态自由，值得。

## 4. 三种运行形态

| 形态 | 命令 | 端口来源 | 鉴权 | 用途 |
|---|---|---|---|---|
| 开发 | `pnpm dev` | 固定 17890 | 仅 Origin 校验（`isDev`） | 前端热更新 |
| 本地跑 | `node apps/server/dist/index.js` | 17890，占用则 0 | 完整（含 token） | 自己日常用 |
| 安装包 | 双击 exe / app | 每次 0（随机） | 完整（含 token） | 分发 |

### 4.1 开发

```jsonc
// package.json（根）
{
  "scripts": {
    "dev": "pnpm -C packages/web dev & pnpm -C apps/server dev",
    "dev:desktop": "pnpm -C apps/desktop dev"
  }
}
```

Vite 配 `server.proxy`，把 `/api` 转发到 `127.0.0.1:17890`，前端代码里 `fetch('/api/rpc')` 无需区分环境。

```ts
// packages/web/vite.config.ts
export default defineConfig({
  base: '/',
  server: {
    port: 5173,
    proxy: { '/api': { target: 'http://127.0.0.1:17890', changeOrigin: false } },
  },
  build: { outDir: '../web-dist', emptyOutDir: true },
})
```

注意 `changeOrigin: false`。设为 `true` 会改写 `Origin` 头，导致 §6 的 Origin 校验失效（开发期会一直 403）。

### 4.2 本地跑

```bash
node apps/server/dist/index.js --port 17890 --open
```

- `--open`：服务就绪后调系统默认浏览器打开带令牌的 URL。
- 未加 `--open`：终端打印一行 `http://127.0.0.1:17890/?t=<token>`，手动点开。
- `Ctrl+C` 退出；同时删除 `runtime.json`。

### 4.3 安装包

外壳启动 → 调 `startServer({ port: 0 })` → 拿到实际端口 → 开窗 `loadURL`。窗口关完即退出进程（§8.2）。

## 5. 本地服务设计

### 5.1 端口与运行时发现

**不使用固定端口 + 重试**。安装包场景下固定端口会与其他软件冲突，而重试逻辑还要处理「上一个实例没退干净」。改用 `port: 0` 让内核分配空闲端口，一次到位。

```ts
// apps/server/src/runtime.ts
import { writeFileSync, unlinkSync } from 'node:fs'
import { homedir } from 'node:os'
import { join } from 'node:path'

const RUNTIME = join(homedir(), '.cloudmusic', 'runtime.json')

export function publishRuntime(info: { port: number; token: string }) {
  writeFileSync(RUNTIME, JSON.stringify({ ...info, pid: process.pid, at: Date.now() }), { mode: 0o600 })
}

export function clearRuntime() {
  try { unlinkSync(RUNTIME) } catch { /* 已不存在 */ }
}
```

`runtime.json` 权限 `0600`，含令牌，不可被其他用户读取。外壳只读 `port`，不读 `token`（token 从 `startServer()` 返回值直接拿，少一次落盘暴露）。

### 5.2 路由表

| 方法 | 路径 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| `GET` | `/api/health` | — | `{ ok, uptime, version }` | 外壳等就绪用，免鉴权 |
| `POST` | `/api/rpc` | `{ path, biz? }` | `{ code, msg?, data? }` | 统一转发，签名在服务端 |
| `POST` | `/api/auth/qrcode` | — | `{ key, qrUrl, expiresIn }` | |
| `GET` | `/api/auth/poll` | `?key=` | `{ status, token? }` | |
| `POST` | `/api/auth/anonymous` | — | `{ token }` | |
| `POST` | `/api/auth/logout` | — | `{ ok }` | |
| `GET` | `/api/audio` | `?u=` | 二进制流 | 透传 Range（§5.4） |
| `POST` | `/api/download` | `{ url, name }` | `{ path }` | 落盘到下载目录 |
| `POST` | `/api/setup` | `{ appId, privateKey }` | `{ ok }` | 首启写入凭证（§7.3） |
| `GET` | `/*` | — | HTML / 静态文件 | 非 `/api` 前缀，SPA fallback |

前端封装只需一个函数（取代 `08` §7.2）：

```ts
// packages/web/src/lib/request.ts
export async function request<T>(path: string, biz: object = {}) {
  const res = await fetch('/api/rpc', {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ path, biz }),
  })
  if (res.status === 401) throw new AuthError()
  if (res.status === 409) throw new SetupRequiredError((await res.json()).missing)
  const body = await res.json()
  if (body.code !== 200) throw new ApiError(body.code, body.msg)
  return body.data as T
}
```

`/api/rpc` 的 `path` **必须做前缀白名单**，只允许 `/openapi/` 开头。否则本服务就成了一个「能签名访问任意网易云接口」的通用代理。

```ts
// apps/server/src/routes/rpc.ts
const ALLOWED = /^\/openapi\/(music|podcast|voice|mv)\//i

app.post('/api/rpc', async (req, reply) => {
  const { path, biz = {} } = req.body as { path?: string; biz?: object }
  if (typeof path !== 'string' || !ALLOWED.test(path)) {
    return reply.code(400).send({ code: 400, msg: 'path not allowed' })
  }
  const envelope = await core.call(path, biz)
  return reply.code(200).send(envelope)
})
```

### 5.3 静态资源与 SPA fallback

```ts
// apps/server/src/static.ts
await app.register(import('@fastify/static'), { root: WEB_DIST, prefix: '/' })

app.setNotFoundHandler((req, reply) => {
  if (req.url.startsWith('/api')) return reply.code(404).send({ code: 404 })
  return reply.sendFile('index.html')      // 路由交给前端
})
```

产物位置需要兼容两种运行环境，用同一个解析函数：

```ts
// 打包后 web-dist 在 resources/web；node 直跑时在仓库根 web-dist
const WEB_DIST = process.resourcesPath
  ? join(process.resourcesPath, 'web')
  : join(import.meta.dirname, '../../../web-dist')
```

`process.resourcesPath` 只有 Electron 环境有值，判断它就能区分两种形态，不需要额外的环境变量。

### 5.4 音频代理与 Range

播放地址是第三方 CDN 直链，**不要假设它带 CORS 头**。稳妥做法是全部走 `/api/audio?u=`，服务端透传 `Range`。

```ts
// apps/server/src/routes/audio.ts
app.get('/api/audio', async (req, reply) => {
  const raw = String((req.query as any).u ?? '')
  if (!isAllowedCdn(raw)) return reply.code(403).send()   // 见下方 SSRF 说明

  const range = req.headers.range
  const upstream = await fetch(raw, {
    headers: range ? { range } : {},
    redirect: 'follow',
  })

  reply.code(upstream.status)
  for (const h of ['content-type', 'content-length', 'content-range', 'accept-ranges']) {
    const v = upstream.headers.get(h)
    if (v) reply.header(h, v)
  }
  return reply.send(Readable.fromWeb(upstream.body as any))
})
```

**必须处理的两个点**：

1. **Range 透传**。不透传的话，`<audio>` 拿不到 `206 Partial Content`，进度条拖不动，长音频起播也会变慢。这是最容易漏的一处。
2. **SSRF 防护**。`u` 是用户可控参数，不校验就等于提供了一个「以本机身份访问任意内网地址」的接口（`?u=http://192.168.1.1/admin`）。白名单按域名后缀匹配：

```ts
const CDN = ['.music.126.net', '.126.net', '.music.163.com', '.163.com']
function isAllowedCdn(u: string) {
  try {
    const { protocol, hostname } = new URL(u)
    return protocol === 'https:' && CDN.some((d) => hostname === d.slice(1) || hostname.endsWith(d))
  } catch { return false }
}
```

如果实测确认某类地址带 CORS，可在前端直连以省一次转发；但只要有一个不带，就得保留代理路径。默认全代理更省心。

## 6. 本地鉴权

这是本地 HTTP 形态特有的、**不能省**的一节。

### 6.1 威胁模型

服务监听 `127.0.0.1`，看似只有本机能访问，实际有三类真实攻击面：

| 攻击 | 手法 | 后果 |
|---|---|---|
| **跨站请求** | 用户在你应用运行时访问任意网页，页面 JS `fetch('http://127.0.0.1:17890/api/rpc', {mode:'no-cors'})` | 消耗你的接口额度；`no-cors` 拿不到响应，但请求已发出并计入额度 |
| **DNS rebinding** | 恶意域名先解析到公网、再解析到 `127.0.0.1`，让浏览器认为同源 | 可读响应体，等于拿到全部接口数据 |
| **本机其他进程** | 其他软件（含恶意脚本）直接请求端口 | 同上，且不受浏览器限制 |

结论：**不能只靠「绑 127.0.0.1」**。绑定只挡住了局域网，挡不住本机浏览器。

### 6.2 四道护栏

| # | 措施 | 拦截目标 | 实现位置 |
|---|---|---|---|
| 1 | 校验 `Host` 头必须是 `127.0.0.1:<port>` 或 `localhost:<port>` | DNS rebinding | 全局 onRequest |
| 2 | 校验 `Origin` / `Sec-Fetch-Site`，跨站直接 403 | 跨站请求 | 全局 onRequest |
| 3 | 启动生成 32 字节令牌，值走 `HttpOnly` Cookie | 本机其他进程 + 二次确认 | 首访交换 |
| 4 | `/api/rpc` 的 `path` 前缀白名单 | 被当通用代理 | rpc 路由内 |

### 6.3 实现

```ts
// apps/server/src/guard.ts
import { randomBytes, timingSafeEqual } from 'node:crypto'

export function createGuard(token: string, devMode: boolean) {
  return async function guard(req, reply) {
    if (req.url === '/api/health') return

    // 1. Host 校验：防 DNS rebinding
    const host = String(req.headers.host ?? '')
    if (!/^(127\.0\.0\.1|localhost):\d+$/.test(host)) {
      return reply.code(403).send({ code: 403, msg: 'bad host' })
    }

    // 2. 跨站校验：现代浏览器必带 Sec-Fetch-Site
    const site = req.headers['sec-fetch-site']
    if (site && site !== 'same-origin' && site !== 'none') {
      return reply.code(403).send({ code: 403, msg: 'cross-site blocked' })
    }
    const origin = req.headers.origin
    if (origin && !/^http:\/\/(127\.0\.0\.1|localhost)(:\d+)?$/.test(origin)) {
      return reply.code(403).send({ code: 403, msg: 'bad origin' })
    }

    // 3. 开发模式免令牌，方便浏览器直开与热更新
    if (devMode) return

    // 4. 令牌校验（Cookie 优先，兼容 header）
    const cookie = parseCookie(req.headers.cookie)['cm_token']
    const given = cookie ?? String(req.headers['x-app-token'] ?? '')
    if (!given || !safeEqual(given, token)) {
      return reply.code(401).send({ code: 401, msg: 'unauthorized' })
    }
  }
}

function safeEqual(a: string, b: string) {
  const x = Buffer.from(a); const y = Buffer.from(b)
  return x.length === y.length && timingSafeEqual(x, y)
}
```

**令牌交换流程**（避免令牌出现在 URL 历史里）：

```
GET /?t=<token>
  ├─ 校验通过 → Set-Cookie: cm_token=<token>; HttpOnly; SameSite=Strict; Path=/
  └─ 302 跳转到 /
```

跳转后地址栏是干净的 `/`，令牌只在 Cookie 里，JS 读不到（`HttpOnly`），XSS 也拿不走。

**首访兜底**：如果用户直接打开 `http://127.0.0.1:PORT`（无 `t` 参数、无 Cookie），返回一个极简页面，提示「请从启动窗口复制的链接访问」，并提供输入框输入令牌。比直接 401 白屏友好。

## 7. 凭证管理

### 7.1 字段分级

先分清四个字段的性质，这决定了谁能进仓库：

| 字段 | 层级 | 是否常量 | 能否进仓库 | 说明 |
|---|---|---|---|---|
| `appId` | 应用 | 是 | 视策略（§7.5） | 应用编号，公开影响小 |
| `appSecret` | 应用 | 是 | 视策略 | 部分链路用于换 token |
| `privateKey` | 应用 | 是 | **推荐不进** | RSA 私钥，能签任何请求 |
| `accessToken` | 用户 | **否**，会过期 | **绝不** | 登录态，泄露等于出借账号 |
| `refreshToken` | 用户 | **否** | **绝不** | 可换取新 accessToken |

`01` 文档错误码 `1406` 即「accessToken 过期」。凡是会过期的都不是常量，不能按「常量密钥」对待。

### 7.2 存储位置

| 环境 | 位置 | 加密 | 优先级 |
|---|---|---|---|
| CI / 容器 | 环境变量 `CM_APP_ID` / `CM_PRIVATE_KEY`（PEM 文本） | 由 CI 密钥托管 | 1（最高） |
| 本机（打包后） | `<userData>/credentials.json` | Electron `safeStorage` 加密 | 2 |
| 本机（node 直跑） | `~/.cloudmusic/credentials.json`（`0600`） | 文件权限 | 2 |
| 开发 | 同 `~/.cloudmusic/` 或 `.env.local` | 无 | 3 |
| 默认 | `config/default.json` | 无，**只放非敏感项** | 4 |

```jsonc
// config/default.json（提交到仓库）
{
  "port": 17890,
  "device": {
    "channel": "cloudmusic-pc",
    "deviceType": "openapi",
    "os": "openapi",
    "appVer": "1.0.0"
  },
  "timeout": 10000,
  "concurrency": 3,
  "credentials": {
    "appId": "",
    "privateKey": ""
  }
}
```

加载顺序为「环境变量 → 本机文件 → 默认文件」，后者被前者覆盖。空值视为未配置。

### 7.3 首启引导

不做「首次运行报错退出」，改为前端引导：

```
启动 → 检测凭证
  ├─ 有 → 正常进入首页
  └─ 无 → /api/rpc 返回 409 { missing: ['appId','privateKey'] }
           → 前端渲染配置页
           → 用户粘贴 → POST /api/setup
           → 服务端校验（appId 非空 + privateKey 能解析成 RSA）
           → 写入 credentials.json（0600）→ 重载
```

```ts
// apps/server/src/routes/setup.ts
app.post('/api/setup', async (req, reply) => {
  const { appId, privateKey } = req.body as { appId?: string; privateKey?: string }
  if (!appId || !privateKey) return reply.code(400).send({ code: 400, msg: 'missing' })
  try {
    createSign('RSA-SHA256').update('probe').sign(privateKey)   // 只验证能否签名
  } catch {
    return reply.code(400).send({ code: 400, msg: 'invalid privateKey' })
  }
  await saveCredentials({ appId, privateKey })
  return { ok: true }
})
```

用「能不能签出一次」来校验密钥，比正则匹配 PEM 头可靠——它同时验证了格式和可用性。

### 7.4 轮换预案

凭证一旦确定可能泄露，需要保证 10 分钟内能换掉：

1. 控制台重置 privateKey（**提交前先确认平台支持这一步**，若不支持则泄露就是永久性的）。
2. 覆盖本地 `credentials.json` 或 CI 环境变量。
3. 重启进程，旧签名立即失效。

**前提**：把「能否重置密钥」当作提交决策的硬门槛。不能重置的凭证不应该出现在任何可能公开的地方。

### 7.5 如果决定提交到仓库

前面的建议是不提交。若确实要提交（例如仓库本身是公开 demo），至少满足三条：

1. **文件名自述**：`config/credentials.public.json`，README 注明「公开测试凭证，非生产用途，随时轮换」。
2. **只含应用级三项**：`appId` / `appSecret` / `privateKey`。`accessToken` / `refreshToken` 永远本地。
3. **保证可轮换**：先验证控制台能重置，再提交。

**不可逆事实**：git 历史是追加的。私钥进过任何一次 commit，即使后续删除文件、加 `.gitignore`，`git log -p` 仍能翻出；force push 之后也可能已被第三方存档。彻底清除需要 `git filter-repo` 重写历史并联系托管方清缓存，且不保证完全失效。

因此「提交密钥」不是「现在问题不大」的判断，而是「做了回不去」的判断。

## 8. 打包

### 8.1 两条路线

| | Electron 壳（推荐） | Node SEA + NSIS |
|---|---|---|
| 原理 | 主进程调 `startServer()`，窗口加载本地端口 | 把 server + 前端打成单 exe，NSIS 封装 |
| 安装包体积 | 约 110–150 MB | 约 50–70 MB（估算，需实测） |
| 开发成本 | 低，配置驱动 | 中，需手写安装/卸载/快捷方式 |
| 自动更新 | `electron-updater` 现成 | 需自建 |
| 多平台 | 一份配置出三端 | 每平台单独打 |
| 进程生命周期 | 窗口关闭即全退，干净 | 需自行处理孤儿进程 |
| 原生能力 | 后续要托盘/通知/全局快捷键直接可用 | 需额外封装 |

**建议先走 Electron 壳**。它的核心价值不是「能出安装包」，而是**进程生命周期管理是免费的**——用户关窗后不会有残留 node 进程占着端口。等确实觉得体积不可接受时，再切 SEA，此时 `apps/server` 一行都不用改。

### 8.2 外壳实现

```ts
// apps/desktop/main.ts
import { app, BrowserWindow, shell } from 'electron'
import { startServer } from '@cloudmusic/server'

let server: Awaited<ReturnType<typeof startServer>> | null = null
let win: BrowserWindow | null = null

if (!app.requestSingleInstanceLock()) app.quit()

app.whenReady().then(async () => {
  server = await startServer({ port: 0, host: '127.0.0.1' })

  win = new BrowserWindow({
    width: 1440,
    height: 900,
    minWidth: 1180,
    minHeight: 720,
    backgroundColor: '#0B0D10',
    titleBarStyle: process.platform === 'darwin' ? 'hiddenInset' : 'default',
    webPreferences: {
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
    },
  })

  win.loadURL(`http://127.0.0.1:${server.port}/?t=${server.token}`)
  win.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url)          // 外链走系统浏览器
    return { action: 'deny' }
  })
})

app.on('window-all-closed', async () => {
  await server?.close()
  server = null
  app.quit()
})
```

**三个细节**：

- `startServer({ port: 0 })` 让内核分配端口，彻底避开「端口被占用」。
- `loadURL` 带 `?t=` 触发 §6.3 的 Cookie 交换，窗口内地址栏（若有）也是干净的 `/`。
- `window-all-closed` 里先 `await server.close()` 再 `quit()`，否则可能残留监听。

### 8.3 electron-builder 配置

```jsonc
// apps/desktop/package.json 中的 build 字段
{
  "appId": "com.example.cloudmusic",
  "productName": "云音乐",
  "directories": { "output": "../../release" },
  "files": ["main.js", "preload.js"],
  "extraResources": [
    { "from": "../../web-dist", "to": "web" },
    { "from": "../server/dist", "to": "server" }
  ],
  "asar": true,
  "win": { "target": ["nsis"], "icon": "build/icon.ico" },
  "nsis": {
    "oneClick": false,
    "perMachine": false,
    "allowToChangeInstallationDirectory": true
  },
  "mac": { "target": ["dmg"], "category": "public.app-category.music" },
  "linux": { "target": ["AppImage"], "category": "Audio" }
}
```

前端与 server 放 `extraResources` 而不是打进 `asar`：`@fastify/static` 需要真实文件路径，asar 内的虚拟路径读不到。`process.resourcesPath` 正好指向这里（§5.3）。

### 8.4 SEA 路线（备选）

Node 20+ 的 Single Executable Application：

```bash
# 1. 生成 blob
node --experimental-sea-config sea-config.json

# 2. 复制 node 二进制并注入
cp "$(command -v node)" dist/cloudmusic
npx postject dist/cloudmusic NODE_SEA_BLOB sea-prep.blob \
  --sentinel-fuse NODE_SEA_FUSE_fce680ab2cc467b6e072b8b5df1996b2

# 3. NSIS 封装为安装包
makensis scripts/installer.nsi
```

`sea-config.json` 需要把 `web-dist` 与 `server/dist` 一起打进 `assets`，运行时用 `sea.getAsset()` 读出到临时目录再交给 `@fastify/static`。这一步比 Electron 繁琐，是 SEA 路线的主要成本。

### 8.5 体积优化（两条路线通用）

- 前端产物 `gzip` 后目标 < 600 KB（见 `08` §11）。
- server 依赖只保留 `fastify` + `@fastify/static`，不引 ORM、不引日志框架（用 `console` + 文件追加）。
- `package.json` 里 `"type": "module"`，避免 CJS/ESM 双份打包。
- Electron 的 `files` 只列必要项，不要把整个 `node_modules` 塞进去。

### 9.3 pre-commit 密钥扫描

```js
// scripts/check-secrets.mjs
import { execSync } from 'node:child_process'
import { readFileSync } from 'node:fs'

const files = execSync('git diff --cached --name-only --diff-filter=ACM', { encoding: 'utf8' })
  .split('\n').filter(Boolean)

const RULES = [
  { name: 'RSA 私钥', re: /BEGIN (RSA )?PRIVATE KEY/ },
  { name: 'accessToken', re: /["']?accessToken["']?\s*[:=]\s*["'][0-9a-f]{40,}/i },
  { name: 'refreshToken', re: /["']?refreshToken["']?\s*[:=]\s*["'][0-9a-f]{20,}/i },
]

let hit = 0
for (const f of files) {
  if (/\.(png|jpg|ico|woff2?|lock)$/i.test(f)) continue
  let text = ''
  try { text = readFileSync(f, 'utf8') } catch { continue }
  for (const r of RULES) {
    if (r.re.test(text)) { console.error(`[check-secrets] ${f}: 命中 ${r.name}`); hit++ }
  }
}

if (hit) {
  console.error('\n提交被拦截。确认无敏感信息后，可用 git commit --no-verify 跳过。')
  process.exit(1)
}
```

```jsonc
// package.json
"simple-git-hooks": { "pre-commit": "node scripts/check-secrets.mjs" }
```

`--no-verify` 这个逃生口要保留——否则一旦误报就卡住正常提交；但它的存在意味着**这道闸只是防手滑，不是防决心**。

### 9.4 CI 门禁

`lint` → `typecheck` → `test` → `check:secrets` → `build`。前四项任一失败不合并；`check:secrets` 同时对全量历史跑一次（`git log -p` 抽样）。

## 11. 与 `08` 的差异汇总

| 项 | `08` 原文 | 本文 |
|---|---|---|
| 进程边界 | Electron 主进程 + 渲染进程 | Node 服务 + 浏览器（Electron 可为壳） |
| 通信 | IPC `window.api.request` | HTTP `fetch('/api/rpc')` |
| 路由方式 | `createHashRouter`（`file://`） | `createBrowserRouter`（`http://`），无需 hash |
| CSP | `connect-src 'none'` | `connect-src 'self'`（要允许同源 fetch） |
| 安全边界 | 进程隔离，无额外校验 | 端口 + 四道护栏（§6） |
| 凭证存储 | `userData/secret.bin` | 多级：env → `~/.cloudmusic/` → `config/` |
| 打包 | `electron-builder` 单包 | 外壳 / SEA 两条路线（§8） |

**唯一没有变的一条**：`privateKey` 与 `accessToken` 不能出现在浏览器可达的位置。IPC 和 HTTP 都满足，只是 HTTP 需要自己补鉴权。
