## 官方开放平台「后台」能力摸底（承接 11-12 的官方路线调研）

用户问「网易云音乐有没有官方后台管理」。结论分三层，别混：

1. **开发者管控台（官方，有）** — `developer.music.163.com/st/developer/controlCenter/*`
   - 实到页面路由只有 5 个：`appList` / `appInfo` / `appManage` / `appAcceptance` / `accountInfo`。
   - 未登录调 `/api/growth/external/openplatform/app/list` 返回 `{"code":351,"message":"用户未登录"}`，确认是登录态后台而非公开页。
   - 从前端 `umi.js` 反查到的管控台 API（即能管什么）：
     - 入驻账号：`account/add|get|update`、`send/captcha`、`user/info/get`(角色)
     - 应用：`app/add|list|get|update`
     - 接口权限：`apigroup/list`（可申请分组）、`app/apigroup/list`（已申请）、`app/apigroup/add`（申请）
     - 上线：`app/online`、`app/offline`、`app/online/date/set`
     - OAuth：`app/oauth/apply`
     - 域名白名单：`dns/list`、`dns/auditupdate`（带审核）
     - 数据验收：`data/acceptance/rule/get|check`、`.../clear`（上线前校验播放上报）
     - 审核流转：`apollo/approve`（提交）、`apollo/close`（撤销）
     - 产品：`product/list|add`；公共配置：`openapi/config/get`
   - **缺**：无调用量/账单/监控看板页（额度只在应用详情里）；无业务侧（用户、订单、内容运营）管理。

2. **音乐人后台（官方，有但无关 API）** — `music.163.com/st/musician`，上传作品/看数据。第三方接入用不到。

3. **业务管理端（必须自建）** — 自己 App 的用户、收藏、播放历史、播放上报记录，官方没有接口给你管，只能在 BFF 后面自己写。

补充事实：开放平台文档共 554 条，分类为 音乐API 301 / 定制API 102 / 播客API 70 / SDK 37 / 厂商接入指南 19 / CMAPI 10 / 个人接入指南 8 / 权益活动 3 / 活动接入 2 / 网易云音认证 2。个人接入指南里含「个人开发者入驻」(docId 46be8cfe3f8b476bb1e8b98e765b75ab)、「常见问题 FAQ」、「CLI」等。

下一步：等用户拿 AppID/PrivateKey，再搭 BFF + 前端骨架（匿名登录 → 搜索 → 播放 最小链路）。

## 用户问「做一个和网易云音乐一样的平台，官方接口支持吗」——逐条核过目录

支持（客户端形态可做到接近完整）：
- 搜索全套（歌曲/歌手/专辑/歌单/MV/播客/热搜/提示词）、推荐（每日推荐、私人漫游、雷达、心动、相似、榜单、banner）、播放地址（128~1999kbps + 批量 + 无法播放 toast 文案）、下载地址、歌词（含逐字）、歌单浏览/广场/标签、收藏歌单/批量加删歌/红心、评论（读+发一级+回复）、专辑/艺人、MV（仅列表/详情/搜索）、播客 70 条、播放记录 15 条（最近播放、听歌排行、跨端续播上报/查询）、一起听 14 条、分享短链。

明确不支持（全目录检索计数为 0）：
- **上传音乐**：`上传` 只命中「生成密钥并上传」= 0 个音频上传接口 → 做不了用户发歌。
- **动态 / 私信 / 粉丝**：0 条 → 做不了社区。
- **创建 / 编辑歌单**：`歌单` 命中 30+，但只有「获取用户创建的歌单列表」「批量添加歌曲到歌单」「批量删除歌单内歌曲」「收藏/取消收藏」——没有新建歌单接口。第三方只能操作已有歌单。

其他硬约束：登录只有匿名/二维码/H5 唤端（用户必须是网易账号）；播放地址带签名短时效、禁止缓存转分发；每人每天调用次数有上限；定制API(102)/SDK(37) 偏商务，个人入驻实际能申请到的 apigroup 可能只是基础子集，需等审核结果确认。

结论话术：能仿出「网易云客户端」，仿不出「另一个音乐平台」；差距不在接口，在版权授权 + UGC + 账号体系。

## 官方文档正文接口（关键发现，以后抓文档直接用）

- 正文接口在另一个域名：`https://interface.music.163.com/api/openplatform/developer/apidoc/get?docId=<docId>`
  - 返回 `{code:200, data:{docId,title,content:"<h2>..</h2>..<table>.."}}`，`content` 就是文档正文 HTML。
  - 之前试的 `developer.music.163.com/api/openplatform/apidoc/detail|get|content` 全部 404，只有 `.../apidoc/search` 可用（列表里 `content` 恒为 null）。
- 分类树接口：`https://interface.music.163.com/api/openplatform/developer/api/doc/category`
  - **一次返回 3MB，`data.subCategory[catId]` 的 `children[]` 里直接带每篇文档的 `content` 全文**，不用逐篇请求。
  - 结构：`data.category=[{id,title}]`（8 个）→ `data.subCategory[catId]=[{id,title,children:[...]}]` → 叶子 `{id,title,content}`，叶子没有 docId 字段，**用 `id` 当 docId**。
  - 去重后 368 篇（站点索引 554 条是因为同一文档挂在多个分类下）。
- 抓取不需要登录，`curl --noproxy '*'` 直连即可。
