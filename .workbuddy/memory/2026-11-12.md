## 修复 git pull 的 TLS 连接失败 (unexpected eof while reading)

- 现象：`git pull` 报 `TLS connect error: error:0A000126:SSL routines::unexpected eof while reading`。
- 根因：项目 `.git/config` 里配置了 `http.proxy = socks5h://127.0.0.1:7897`，但本机代理 `verge-mihomo`(Clash Verge, PID 35596) 只监听 `127.0.0.1:7897` 且该端口只支持 HTTP 代理；SOCKS 隧道能建立，但 TLS Client Hello 之后被断链。
- 修复：`http.proxy` 改为 `http://127.0.0.1:7897`，并新增 `http.version = HTTP/1.1`（降低 HTTP/2 在代理下被复位的概率）。原有 `http.sslBackend = openssl` 保留。
- 环境事实：直连 github.com 超时不通，必须走代理；系统代理(WinINET)也是 `127.0.0.1:7897`。7897 链路约 20% 概率 TLS 抖动(4/5 成功)，建议在 Clash Verge 换节点或开 TUN/全局模式，偶发失败重试即可。
- 第二个问题：远端 `useryize/CloudMusic` 是**空仓库**（2026-11-12T03:49:40Z 创建，size=0，branches=[]，从未 push）；本地目录也只有 `.git`、无任何提交。网络修好后 `git pull` 改为报 `Your configuration specifies to merge with the ref 'refs/heads/main' ... no such ref was fetched`。需先由有代码的一方做首次提交并 push，或确认仓库地址是否正确。

## 项目定位：仿网易云音乐播放器 — 数据来源调研结论

- 官方通道（合规首选）：`developer.music.163.com` 开放平台，2026 年支持成年实名「个人开发者入驻」，审核后拿 AppID + PrivateKey（RSA2048/PKCS8），有每日调用次数上限；接口前缀 `/openapi/music/basic/...`（歌单详情、每日推荐等），公共参数含 appId / signType=RSA_SHA256 / accessToken / timestamp。官方 CLI `@music163/ncm-cli`、官方 Skill 仓库 `NetEase/skills`。播放是控制官方 App / mpv，不提供裸音频直链。
- 第三方自建（仅学习自用）：`Binaryify/NeteaseCloudMusicApi` 已归档且代码清空 —— 是网易法务函要求下线，不是普通停更。活跃接班为 `NeteaseCloudMusicApiEnhanced/api-enhanced`（MIT，npm `@neteasecloudmusicapienhanced/api` 4.41.1，Docker `moefurina/ncm-api`，文档约 400+ 接口）。其他实现：Rust `SPlayer-Dev/ncm-api-rs`、Go `chaunsin/netease-cloud-music` / `go-musicfox/netease-music`、Python `XiYang6666/EvenBetterNeteaseResolver`、聚合 `metowolf/Meting`。
- 结论：要上线走官方平台；自用 demo 用 enhanced Docker。公共实例不可用（官方文档明确警告会泄露账号 Cookie）。第三方项目 MIT 只覆盖代码、不覆盖音乐版权。
